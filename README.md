# 아침 마음 온도계 · 공용 기기 배포본

교실 기기 한 대의 같은 브라우저에서 학생들이 차례로 작성하는 앱입니다. 개인 휴대폰 접속이나 학생별 계정은 사용하지 않습니다.

## 배포

현재 배포는 **GitHub Pages**를 사용합니다: https://yalibk-source.github.io/morning-mind-thermometer/
`main`에 변경을 올리면 `.github/workflows/pages.yml`이 테스트, 빌드, Pages 배포를 순서대로 실행합니다. 저장소 Settings → Pages의 Source는 GitHub Actions입니다. Netlify에 대한 아래 내용은 다른 호스팅으로 이전할 때 참고하는 방법입니다.

## 데모 체험

- 처음 방문한 브라우저에 실제 명부·기록이 없다면 가상 학생 8명과 최근 3주간의 예시 기록 164건으로 데모를 시작합니다. 얼굴은 직접 만든 가상 인물 일러스트입니다. 실제 학생 사진이 아닙니다.
- 오늘은 4명이 기록을 마쳤고, 남은 4명으로 학생 입력을 시연할 수 있습니다.
- 상단의 **교사 화면 체험**으로 로그인 없이 현황분석, 학생관리, 일일 및 누적기록을 확인할 수 있습니다. 이 바로가기는 데모에서만 동작합니다.
- 데모의 추가·입력·메모·비밀번호 변경 등은 메모리에만 적용됩니다. 새로고침 또는 **데모 새로 시작**으로 원래 예시가 복원됩니다. 데모 백업은 실제 학급 모드로 가져올 수 없습니다.
- **실제 학급 사용으로 전환**하면 해당 브라우저의 실제 명부·기록을 불러옵니다. 기존 실제 데이터가 있는 브라우저는 업데이트만으로 데모로 바뀌지 않습니다.
- 화면 오른쪽 아래 제작자: **효양고 이은비**.
- ‘기분 직접 쓰기’와 ‘선생님께 한 마디’ 모두 음성 입력을 지원하며, 브라우저가 지원하지 않으면 글자로 입력할 수 있습니다. 기분은 최대 6자입니다. 입력 취소나 단계 이동 시 마이크 인식은 중단됩니다.
- 학생관리의 **삭제**는 학생을 명부에서 숨기고 **삭제한 학생** 목록으로 이동합니다. 기존 기록을 보존하며 복원할 수 있습니다. 전출·보관 기능은 별도로 유지됩니다.

- **기존 Netlify 사이트 업데이트:** `netlify-deploy.zip`을 풀고, 기존 사이트의 Deploys 화면에 압축을 푼 폴더를 올립니다. 폴더 바로 아래에 `index.html`, `_headers`, `assets/`가 있어야 합니다. ZIP 자체보다 압축을 푼 폴더를 올리는 것이 확실합니다.
- **Git 연결:** 이 프로젝트를 저장소에 넣고 Netlify의 build command를 `npm run build`, publish directory를 `dist`로 설정합니다. `netlify.toml`에도 같은 설정이 있습니다.
- 로컬 작업: `npm ci` → `npm test` → `npm run build`. `npm run preview`로 `http://localhost:4173`에서 확인합니다.

Vue와 CSS는 빌드 결과에 포함됩니다. 배포본은 외부 CDN을 불러오지 않습니다. 인터넷이 끊긴 상태의 재접속까지 보장하는 오프라인 앱은 아닙니다.

## 첫 사용

1. 교실 기기에서 **앞으로 계속 사용할 동일한 주소·동일한 브라우저 프로필**로 접속합니다. 시크릿 모드는 사용하지 않습니다.
2. 선생님 로그인 후 학생관리에서 명부를 등록합니다. 초기 비밀번호는 기존 원본의 `3333`입니다. 학생들에게 화면을 넘기기 전에 선생님 화면에서 직접 변경합니다.
3. 학생 모드로 나갑니다. 학생은 이름 확인 → 기분 선택 → 온도 확인 → 한 마디(선택) 순서로 작성합니다.
4. 제출 후 5초 뒤 처음 화면으로 돌아갑니다. 90초 미사용 시 미완성 입력이 사라집니다. 교사 화면은 3분 미사용 시 잠깁니다.
5. 날짜는 기기의 날짜·시간을 사용합니다. 기기 시간을 한국 시간으로 맞춥니다.

새 브라우저에서는 학생과 기록이 없는 상태로 시작합니다. 기존 사이트에서 저장된 데이터는 기존 키를 그대로 사용해 유지합니다. 예전 앱에서 자동 생성된 예시 명부·기록이 남아 있다면 실제 기록 여부를 확인하고 백업한 뒤 위험 작업의 초기화를 사용하세요. 앱이 자동으로 실제 기록과 예시를 추정해 삭제하지는 않습니다.

## 보관과 백업

- 데이터는 **이 사이트 주소의 이 브라우저 저장소(localStorage)**에만 있습니다. 서버 전송·다른 기기 동기화는 없습니다.
- 브라우저 데이터 삭제, 프로필 변경, 기기 고장, 주소 변경 시 기존 데이터에 접근할 수 없게 됩니다.
- 학생관리의 **JSON 백업 저장**을 정기적으로 사용하세요. 백업에는 명부·사진·감정·메시지·교사 메모가 들어갑니다. 비밀번호는 포함하지 않습니다.
- 복원은 명부와 기록을 교체합니다. 먼저 현재 데이터를 백업하고 복원하세요. 다른 주소로 옮길 때도 JSON으로 이전할 수 있습니다.
- CSV는 현재 검색 결과 내보내기용입니다. 복원용은 JSON입니다.
- 전출·보관은 과거 기록을 유지하며 재적 복귀할 수 있습니다.

## 보호 범위

교사 비밀번호는 공용 화면에서 우발적으로 교사 영역에 들어가는 것을 막는 **로컬 화면 잠금**입니다. 서버 인증이 아니므로 기기와 개발자 도구에 접근할 수 있는 사람에게서 데이터를 보호하는 수단은 아닙니다. 교실 기기 자체의 계정·잠금도 관리하세요. 기존 구조와의 호환성을 위해 비밀번호도 브라우저 저장소를 사용합니다.

음성 입력은 브라우저 제공업체의 서비스를 사용할 수 있습니다. 공용 기기에서 필요할 때 선생님이 마이크 권한과 사용 여부를 결정하세요. 직접 입력만으로 모든 기록을 완료할 수 있습니다.

감정 분류와 평균은 상담 진단이 아닙니다. 기록 수와 개인 상황을 함께 보고 교사가 확인합니다.

## 검증

`npm test`는 Vue 템플릿 컴파일, 빈 최초 실행, 감정 필수 선택, 단계 이동, 저장, 중복 제출 차단, 제출 후 자동 복귀, 필터, 지원 상태 저장, 보관·복귀, 저장 실패 시 제출 취소를 검사합니다. `npm run build`는 JS 구문 검사와 자체 포함 배포본 생성을 수행합니다.

자동 브라우저가 이 환경의 localhost에 연결되지 않아 최종 화면의 시각 검증은 완료하지 못했습니다. 실제 교실 브라우저에서 배포 후 학생 1명의 입력 흐름과 JSON 백업·복원을 확인하세요. 테스트 기록을 실명으로 만들 필요는 없습니다.
